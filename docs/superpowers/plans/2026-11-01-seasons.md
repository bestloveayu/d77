# Mobile Season Sources Implementation Plan

**Goal:** Manage tested season sources from the authenticated mobile board without redeployment or business-data writes.

**Architecture:** Keep a private registry in the existing shared Durable Object. Test source configurations server-side, bind the result to user, configuration digest and registry revision, then recheck before saving. Route each season/configuration to an isolated Durable Object so snapshots, baselines, events and read receipts cannot leak across seasons.

**Constraints:** No edits to the local order system or GAS. Viewer accounts cannot manage sources. Source IDs remain server-private and never go into the public repository. Failed validation or source reads leave the saved source untouched. Demo setup is clearly marked and makes no network writes.
